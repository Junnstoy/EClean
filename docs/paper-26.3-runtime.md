# Paper 26.3 实机验证（2026-10-03）

## 环境和结论

- 官方 Paper **26.3 build 143**, `26.3-143-main@ff3655a`，Java **Temurin 25.0.4.1+1**。
- 隔离的本机测试服，仅绑定 `127.0.0.1:25579`；无真实玩家登录。
- 初次测试使用此前交付的原始功能 JAR，发现区块卸载判断错误。修复后重新执行全部场景，并完整重启一次服务器。
- 修复版 **57 项单元/MockBukkit 测试通过**；真实服务端 **34 条断言通过（32 个不同检查，两个启动检查在重启时重复）**，没有失败。
- 本结果针对普通 Paper，不代表 Folia、其他服务端实现或所有第三方插件组合均兼容。

## 实测发现并修复的问题

原实现调用 `World.isChunkInUse(x,z)` 排除玩家使用的区块。但在这个 Paper 构建的 `CraftWorld` 字节码中，该方法直接调用 `isChunkLoaded(x,z)` 并返回。因此，所有已经加载的候选都被当作“使用中”：原版观测到检查 2160 次、跳过 2160 次、请求 0 次。

修复为通过 `Chunk.getPlayersSeeingChunk()` 检查实际观察玩家，继续保留玩家附近半径、强制加载和插件票据保护。观察玩家信息未知、调用异常或相关 API 缺失时继续拒绝卸载。没有强制删除票据或绕过服务器安全卸载队列。

| 红石抑制 | 观察到实际电流上升被保持旧值；抑制模式下 A 世界 28 次下降沿正常通过；侦测器和红石线未被删除 |

| 数据保存 | 初次显式保存后再放置的钻石块，在实际卸载并重新加载后仍存在；完整 JVM 重启后仍存在 |

| 停用清理 | 重载关闭模块会释放状态；完整重启后再启用/停用插件，两个服务均清空且没有残留活动任务 |

第一次卸载结果观测时累计 72 次请求入队，但**不代表卸载了 72 个区块**。底层票据可能让请求未最终卸载。上述目标区块以卸载事件和实际加载状态单独确认。

## 红石行为限制

实测双侦测器时钟在一次上升沿被抑制后停止，冷却结束后没有自行恢复。`suppress` 不是保证自动恢复的临时暂停，电路可能需要玩家手动触发。测试使用 20 tick 窗口、上限 2、连续 2 窗口、60 tick 冷却，以尽快覆盖抑制路径；不是生产阈值推荐。
