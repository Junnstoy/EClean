## 测试内容

- 启动、配置加载、旧版音效别名，垃圾桶/密集实体菜单构造和图标更新。
- 实体/材料 → 世界 → 默认的字段优先级，手动世界范围，关闭世界覆盖后恢复默认，命名保护、乘客保护、书与笔材料别名。
- 密集实体精确上限、世界上限为 0、同一 tick 再次清理时不多删。
- 三个开关的即时启停、保存、重载、权限拒绝、非法参数拒绝、重启持久化；非法配置不替换有效清理配置。
- 在测试世界定时切换真实红石块电源，由服务器产生原生红石事件；验证报告模式不抑制、忽略世界、上升沿抑制及下降沿放行，方块保留。
- 闲置延迟、请求成功、实际 ChunkUnloadEvent 且 isChunkLoaded=false，已修改方块重新加载和 JVM 重启后保留；存在强加载/插件票据 API 的版本还验证其保护。
- 插件禁用后状态和计划任务释放。

单元测试还覆盖扫描/请求预算、拒绝请求、无效参数、未知保护状态、保存失败不改变运行配置，以及垃圾桶物品自定义堆叠上限等。

## 修复与测试调整记录

1. 旧包内存在 260 个 Java 11 类，不能用于 Java 8；固定 Kaml 0.55.0 后，本次产物包含 1925 个 Java 8 类及 32 个 Java 5 类，没有更高字节码。
2. 1.8 同 tick 内失效实体仍留在区块列表，可能挤占上限，已在清理时排除。
3. 票据制的部分中间版本中 isChunkInUse 只是 isChunkLoaded，改用能力分支；缺少观察玩家接口时仅处理无玩家世界，详见兼容说明。
4. 1.17 的测试世界/区块激活后再校验实体与重启读取；补充区块文件诊断。本轮首次关服后的区块文件含钻石块调色板，重启稳定读取 DIAMOND_BLOCK，所有断言通过。
5. 1.12.2 首轮固定等待 300 tick 未等到目标区块，曾有 2 项测试失败：请求预算需要处理较多初始区块。探针改为按实际完成状态轮询、最长 1200 tick；同一插件 JAR 重测 39/39 通过。该调整没有增大插件预算，也没有以请求数代替实际卸载。
6. 旧服务端统计请求曾被自动审批阻止；最终测试目录显式关闭 mcstats、bStats、snooper，使用本地监听。此项未改动生产插件的统计配置。

## 结论边界

本报告证明表列 Paper 构建和 JDK 上的上述场景。未覆盖每个补丁版本、Spigot 实服、Folia、混合核心、第三方插件组合、真实在线玩家距离/观察区块、真实玩家 GUI 点击、全部自然红石电路或长期性能。老版本不存在的票据/强加载保护属于不适用，因此断言数不同。

部分有票据却无观察玩家接口的版本，区块卸载仅作用于无玩家世界；世界规则和红石不受此限制。红石抑制不拆除电路，也不承诺冷却结束后时钟自动恢复。具体行为见 [兼容说明](compatibility.md)。
